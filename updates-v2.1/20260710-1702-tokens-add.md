# 20260710-1702 — Add `tokens` skill + `HOST_WORKSPACE_PATH` env

**Affects** : v2.1 devcontainers deployed before 2026-07-10 that do
not yet ship the `tokens` token-tracking skill under
`.devcontainer/skills/tokens/` and do not have
`HOST_WORKSPACE_PATH` in their `containerEnv`.

**Symptom** : no per-project Stop-hook token/cost logs, no
`node ~/.claude/tokens/recap.js` cross-container aggregation, and
inside the devcontainer `echo $HOST_WORKSPACE_PATH` is empty. The
skill's `lib/project-id.sh` falls back to `pwd` for the host path
column, so multi-devcontainer setups end up with meaningless
`/workspace` paths in the recap table.

**Fix** : ship the `tokens` skill tree (17 files under
`.devcontainer/skills/tokens/`) and inject the real host path into
the container via `containerEnv.HOST_WORKSPACE_PATH =
${localWorkspaceFolder}`. VS Code resolves that expression at parse
time — no docker socket exposure, no `/proc/mountinfo` parsing.

The skill captures each `Stop` event, writes one JSONL line per
event to `<project-root>/.claude/tokens/logs/YYYY-MM/<sid>.jsonl`,
tags it with the true host path, and prices it via a 5-source
Anthropic pricing cascade. `recap.js` on host unions every
`claude-code-config-*` docker volume into a single per-project
spend table. All consumer tools (`recap`, `refresh-pricing`,
`install`) run standalone — no Claude runtime required.

Design canon :
`plans/tokens/ROLLOUT.md`. Full technical inventory :
`plans/tokens/EXISTING.md`.

## Apply

Run from your downstream project root (the one containing
`.devcontainer/`), after the
[Targeted updates bootstrap](../UPGRADE-v2.md#targeted-updates-updatesname)
populates `.tmp/devcontainer-updates/` :

```bash
git apply --check .tmp/devcontainer-updates/updates-v2.1/20260710-1702-tokens-add.patch
git apply        .tmp/devcontainer-updates/updates-v2.1/20260710-1702-tokens-add.patch

cp -r .tmp/devcontainer-updates/templates/v2/skills/tokens .devcontainer/skills/tokens

git add .devcontainer/devcontainer.json .devcontainer/skills/tokens
git commit -m "feat(tokens): add token-tracking skill + HOST_WORKSPACE_PATH env"
```

Then, in VS Code, run **Dev Containers: Rebuild Container** (Command
Palette : `Ctrl+Shift+P` / `Cmd+Shift+P` → type "rebuild"). The
rebuild is required to pick up the new `containerEnv` entry — a
plain restart is not enough.

The `.patch` only touches `.devcontainer/devcontainer.json`. The
17-file skill tree ships via the `cp -r` step (see
[updates-v2.1/20260703-1242-add-scan-deps-shell-command.md](20260703-1242-add-scan-deps-shell-command.md)
for the same shape).

## Rollback

```bash
git revert <commit-hash>
```

`git revert` unstages the two file changes but leaves the
17-file skill tree on disk (the copied files were tracked in the
same commit — revert removes them from the index and working
tree). If you want to keep the files around for later, revert only
`.devcontainer/devcontainer.json` :

```bash
git checkout HEAD~1 -- .devcontainer/devcontainer.json
git commit -m "revert(tokens): drop HOST_WORKSPACE_PATH env, keep skill"
```

Then rebuild the devcontainer again. The Stop-hook keeps writing
logs but `host_workspace_path` in the config will be empty (falls
back to `pwd`, the pre-fix behavior).
