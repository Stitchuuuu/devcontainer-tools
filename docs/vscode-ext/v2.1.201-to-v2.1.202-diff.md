### 3. New feature keys

Config values / capability flags introduced in the model dispatch
plumbing :

- `SSEHttpError` — new error class for server-sent-events streaming.
  Probably distinguishes network-level failures from Anthropic API
  errors (finer-grained retry logic).
- `adaptive_thinking` — new thinking mode variant. Was
  `default_on`/`off` previously ; now there's an adaptive third rail.
- `context_management` — new capability toggle. Probably relates to
  automatic context compaction / truncation.
- `mid_conv_system` — mid-conversation system prompt handling.
  Probably lets the ext inject a system prompt mid-stream instead of
  only at conversation start.
- `lean_prompt` — new prompt mode. Streamlined variant.
- `fast_mode` — corresponds to the /fast Claude Code toggle. Probably
  now surfaced as a first-class capability the model dispatcher can
  see.
- `overflow` — probably context-overflow handling policy.
- `rejects_disabled_thinking` — flag distinguishing which models
  refuse a request when `thinking: off` is passed.

**Effort levels** — 3 new granularity constants :

- `effort` (base)
- `max_effort`
- `xhigh_effort` (a step above max)

Probably driving compute-budget control per request.

**Model family labels** — 4 new bare strings :

- `haiku`, `sonnet`, `mythos`, `fable`

Match the 4 emerging model families. `mythos` and `fable` are the
new code-names — not yet in the marketplace, but wired in the
dispatcher.

### 4. `native-binary/claude` bumped

Size delta : 248 MB (v201) → 258 MB (v202) = **+10 MB**. Almost
certainly the underlying Claude Code CLI binary got a version bump
matching the ext version, with the same set of features baked in.

## What did NOT change (surface confirmation)

Verified explicit non-changes to reassure our patch-set stability :

- `onDidReceiveMessage` chokepoint in `setupPanel()` — same shape (3
  call sites, same regex captures `(panel, msg, comms)`).
- `sendRequest(sid, req, abort)` signature — the requestId generator
  function was renamed (`Y3()` on 2.1.145 → `Hs()` in 2.1.202), but
  the surrounding structure is identical. Our patch already uses
  `\w+\(\)` for the generator name so it survives.
- `handleToolPermissionRequest` in the webview — same `Q = new Gn(…)`
  ; same `Q.onResolved(…)` ; same
  `this.permissionRequests.value.filter(…)` shape. The webview-side
  intercept anchor is unchanged.
- `class Gn` fields (`channelId`, `toolName`, `inputs`, `suggestions`,
  `resolved`) and methods (`accept`, `reject`, `onResolved`) —
  identical. Our `Q.accept(input, perms)` / `Q.reject(msg, false)`
  contract holds.

## Impact on our patches

**None.** The 7 patches (5 pre-existing + 2 new) all apply cleanly on
pristine v2.1.202 with zero syntax errors on both `extension.js` and
`webview/index.js`. The version-adaptive naming in
`icon-fix-open-in-current-panel.py` (step 1/6) switches the enum from
`"primary"` to `"active-panel"` on 2.1.202+ — pure future-proofing
against a hypothetical Anthropic wiring of `"primary"` that hasn't
happened yet.

## Compatibility with our devcontainer configs

On 2.1.202+ the two config files below need updating **only when the
image bumps to 2.1.202+** — currently we're on 2.1.145, no action
required :

- `.devcontainer/devcontainer.json` :
  `"claudeCode.preferredLocation": "primary"` → `"active-panel"`
- `.devcontainer/vscode-settings.jsonc` : same.

The change is idempotent : if you set `"active-panel"` on a 2.1.145
container, our patch on that version added `"primary"` to the enum
(not `"active-panel"`) so VS Code will reject the setting as invalid.
The migration is version-locked : bump image + config in the same PR.
